## 프로젝트 소개

![Untitled](./images/%EC%9E%90%EB%8F%99%EC%99%84%EC%84%B1_1.png)

하나투어의 자동완성은 **지역명 / 패키지 판매상품명 / 호텔상품**만 자동완성 키워드로 노출되고 있다. 또한 매칭되는 한글에 대해서만 자동완성이 표현되고 있다.

사용자 검색 로그를 기반으로 하나투어의 데이터 이외의 사용자 로그데이터를 자동완성으로 노출할 수 있도록 한다. 또한 영역을 분리하여 영역별 정렬을 재정의 한다.

### 지역 영역 정렬

- 도시별 공항 개수
- 도시별 수도 여부
- 도시별 호텔 판매 합
- 도시별 호텔 개수

### 호텔 영역 정렬

- 최근 3개월 예약수
- 호텔 판매금액
- 검색키워드와 호텔 이름간의 정확도

> ***( 100 * 검색어길이 ) / 호텔명길이***
> 

### 사용자 로그 영역 정렬

- 검색키워드와 로그간의 완전 일치 여부
- 문서 개수

### 초성검색

검색어에 `ㅅㅇㅍ` 이라고 검색이 들어오게 되어도 `사이판`이 검색이 가능하도록 처리한다.

### 한영변환 검색

하나투어를 `gkskxndj` 라고 검색해도 검색이 가능하도록 처리한다.

### 전방/후방 색인

Elasticsearch의 edge_ngram을 색인시, 후방일치가 가능하도록 하기 위해, `Reverse Filter`를 이용하여 추가 색인을 진행한다.

```json
{
  "analysis": {
    "analyzer": {
      "edge_ngram_rear_analyzer": {
        "type": "custom",
        "tokenizer": "suggest_tokenizer",
        "filter": [
          "trim",
          "lowercase",
          "reverse"
        ]
      }
    },
    "tokenizer": {
      "suggest_tokenizer": {
        "type": "edge_ngram",
        "min_gram": 2,
        "max_gram": 48,
        "token_chars": [
          "letter"
        ]
      }
    }
  }
}
```

### 검색결과 캐싱으로 속도 향상

하나투어는 기본적으로 키워드 중심의 검색이며 중복되는 검색어가 많다. 이에따라 스프링에서 제공하는 `@Cacheable`을 사용하여 검색 부하 및 속도를 증가 시킨다.

자동완성 배치가 수행되고 나서는 기존의 캐시를 삭제하도록 한다.

### 로그 키워드 그룹핑

사용자 로그의 데이터 중, 동의어 확장을 하여 순서에 상관없이 토큰이 같다면, 같은 키워드로 간주한다. 이후 그룹을 대표하는 검색어를 선정한다. ( Doc Count )

## 프로젝트 성과

---

### 사용성 개선

상품명만 노출되고 있어서 보여줄 수 있는 상품의 한계가 존재한다. 이를 하나투어에서 보여주고 싶은 키워드(어드민)와 사용자 검색 로그를 기반으로 보다 `다양한 상품을 탐색`할 수 있는 자동완성 키워드를 제공한다.

기존의 자동완성은 카테고리영역으로의 이동으로 인하여 클릭시 특정 상품에 대해서만 노출된다. 이를 `통합검색결과`으로 안내함으로써 사용자에게 많은 데이터를 노출하고 선택할 수 있도록 한다.

## 트러블 슈팅 경험

---

### 검색어 하이라이트 이슈

자동완성의 기능을 Elasticsearch의 `edge_ngram` 색인 방식으로 구현하고자 한다. 이때, Elasticsearch에서 제공하는 하이라이트 검색을 이용하여 매칭되는 부분만을 하이라이트 태깅이 이루어져야 한다.

하지만 결과를 확인하면 띄어쓰기의 `토큰단위로 전체 하이라이트 태그가 적용`이 되어버렸다.

### 원인

`Filter 단계에서 edge_ngram을 정의`하고 analyzer의 단계로 추가하게 되면, 토큰 분석 이후의 단계가 되므로 토큰의 Offset이 정의된다. 정의된 Offset은 토큰의 시작과 끝 지점이며, 이때 필터에 의해 색인 토큰이 edge_ngram으로 분리가 된다고 한들, `Offset의 위치값은 변하지 않는다`.

### 해결

`edge_ngram을 Tokenizer 단계로 변경`한다. 그럼으로써 토큰 분석 단계에서 각각의 토큰이 분리가 될 것이며, 이때 분리된 토큰별로 Offset을 지정하게 된다. 이후 하이라이팅 값은 매칭된 부분만 정상적으로 노출된다.

해당 이슈에 대해서는 블로그에 예제와 함께 자세히 기술

[블로그 URL - Elasticsearch 분석 위치에 따른 Offset 차이](https://velog.io/@mertyn88/Elasticsearch-분석-위치에-따른-차이)

## 아쉬운 점

자동완성은 사용자가 검색어를 작성하기전, 완성된 검색어를 `완성` 해서 보여주는것이라고 생각한다. 그렇다면, 노출되는 키워드들은  어떤 기준으로 정렬이 되어야 할까? 프로젝트마다 기준이 다르겠지만 나는 이렇게 변경되었으면 했지만 이번 프로젝트에서는 구현하지 못한 아쉬움이 있다.

### 사용자 로그 기간별 검색량에 따른 가중치 조절

여행사는 계절의 영향을 많이 받는데 6개월전에 많이 입력한 검색어와 일주일전에 많이 입력된 검색어는 아무리 6개월전이 많아도 `일주일 전의 검색어가 상위`에 올라가야한다. 

> 현재는 수집기간을 한달로 잡아서 처리하였다
> 

### 사용자 로그 정확도 조절

정확도를 계산하는데 입력한 검색어의 길이와 실제 상품, 또는 노출되는 검색어의 길이로 백분률 하여 계산한다.

자동완성은 직접 `작성하기 어려운 검색어를 보여주는것`이라고 생각된다. 몇글자 차이 안나는것이 상위에 올라오는것 보다는 길이가 길거나, 한글과 영문이 혼합되어 있거나, 길이가 길어서 타이핑 하기 어려운 자동완성 리스트가 상위에 노출되어야 한다.
